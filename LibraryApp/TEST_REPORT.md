# TEST_REPORT.md — отчёт о тестировании LibraryApp

## 1. Объект тестирования
Консольное приложение **LibraryApp** на C# (.NET 8) для учёта книг библиотеки.
Назначение — регистрация книг, выдача, возврат и поиск по идентификатору.

## 2. Методика тестирования
- ручное функциональное тестирование по сценариям (корректные операции и граничные случаи);
- отладка в Visual Studio: точки останова в `BorrowBook`, `ReturnBook`, `FindBook`, пошаговое выполнение (F10/F11), окна Locals и Watch;
- статический анализ кода: анализаторы .NET (AnalysisLevel = latest-Recommended), проверка именования, XML-документации, обработки исключений.

## 4. Результаты инспекции кода
- **Отсутствие проверки на null** в `AddBook` и результатах `FindBook` — добавлены проверки с понятными сообщениями об ошибках.
- **Нарушение именования** — локальные переменные приведены к camelCase, классы и методы — PascalCase.
- **Отсутствие XML-документации** — добавлены summary для всех публичных классов и методов.
- **Смешение ответственности** — проверки вынесены в начало методов (guard clauses), методы стали короче и выполняют одну задачу.
- **Пустых catch-блоков нет**, исключения не перехватываются «вслепую» — ошибки обрабатываются через явные проверки состояния.

## 6. Контрольные вопросы (кратко)
1. **Debug vs Trace.** Debug компилируется только в Debug-сборке ([Conditional("DEBUG")]) — для отладки разработчиком. Trace работает и в Release ([Conditional("TRACE")]) — для диагностики у пользователя.
2. **Debug.WriteLine в Release** не выполнится: атрибут Conditional убирает и вызов, и код метода на этапе компиляции.
3. **[Conditional("DEBUG")]** исключает вызовы метода из сборки, если символ не определён; метод должен возвращать void. Пример — DumpState() для дампа состояния объекта.
4. **Debugger.** IsAttached — проверка под отладчиком; Break — остановка при отладке; Log — сообщение в окно вывода; Launch — запуск процесса с отладчиком.
5. **Удаление отладочного кода в Release** — потому что остатки вывода могут раскрыть внутреннее устройство, замедлить работу и запутать пользователя.
